8// This must NOT live in `namespace config` with a class named `Config` and a
9// `GetConfig()` free function: the main application defines an unrelated,
10// much larger config::Config/config::GetConfig() in
11// src/application/config/Config.hpp. Since this plugin is a separate dylib
12// (dlopen'd, not linked against application_core) but shares the running
13// process, an identically-named-and-namespaced inline GetConfig() is a One
14// Definition Rule violation — the dynamic linker can bind a call in this
15// plugin to the *main app's* config::GetConfig() (a strong symbol beats this
16// header's weak/inline one), returning a real, large config::Config object
17// while this plugin's compiled code still uses the small local struct's
18// field offsets. Writes like `ollamaBaseUrl = "..."` then land inside
19// whatever real member happens to sit at that byte offset in the actual
20// config::Config object — in practice, FieldTranslator's internal map,
21// corrupting it. Namespaced under `ai` (matching this plugin's other
22// headers) instead, so the symbol can never collide with the app's.
